# Docs For Codex

Эта папка хранит короткую рабочую документацию для Codex и задач, которые нужно передавать между итерациями. Документы должны помогать быстро понять текущее состояние проекта, не заменяя код и инспектор Unity.

## Как вести документацию

- Пишите только то, что влияет на дальнейшую разработку: текущие системы, важные ограничения, открытые задачи, критерии готовности.
- Для задач используйте отдельные файлы в `DocsForCodex/Tasks`.
- В задаче обязательно фиксируйте проблему, ожидаемое поведение, затронутые файлы и критерии проверки.
- Если задача связана с WebGL, отдельно указывайте, что нужно проверить в Editor Play Mode и в WebGL build.
- Не описывайте устаревшие варианты, если они уже не используются. Старые прототипные скрипты лучше упоминать только как источник идей.
- После реализации задачи обновляйте статус в ее файле и добавляйте короткую заметку о решении.

## Текущий контекст проекта

Проект совмещает базовую систему планеты другого разработчика и нашу механику полета/терраформинга рядом с поверхностью.

Основная планета находится в `Assets/Scripts/Planet/Planet.cs`. В ней сейчас живут генерация тайлов, вода, визуальные оверлеи, клики, HUD и экономика.

Наша интеграционная механика полета находится в `Assets/Scripts/HybridTerraform/PlanetFlyTerraformSkill.cs`. Скилл запускается из UI, создает/использует корабль, подводит камеру ближе к планете и во время полета терраформирует область рядом с кораблем.

## Важные ограничения

- Цель по платформе: WebGL, поэтому шейдеры и runtime-материалы должны быть совместимы с WebGL/URP и не зависеть от неподдерживаемых фич.
- Runtime-цвета планеты должны работать без editor-only API.
- Если объект создается во время игры, его материал должен иметь надежный fallback, чтобы в WebGL не появлялся розовый материал.
- Логика высоты корабля должна учитывать не только меш земли, но и воду, если вода находится выше земли.
